# Econet Monetization & Proof Plan

## Objective

THUSO must create measurable economic value for Econet Telecom Lesotho rather than merely add an AI interface.

## Revenue/value streams

1. **AI access revenue**
   - THUSO can drive paid EcoAI/AI access packages.
   - Measure: activated paid AI users, package revenue, retention, incremental AI revenue.

2. **Data/connectivity revenue**
   - AI usage creates recurring data consumption.
   - Measure: incremental data sessions/bytes and ARPU for THUSO-linked cohorts versus a matched baseline.

3. **EcoCash transaction value**
   - THUSO turns conversational intent into permitted payment and commerce flows.
   - Measure: transaction count, GMV, successful transactions, active wallet users and incremental wallet activity attributable to THUSO.

4. **Enterprise/public-sector AI services**
   - Econet can sell THUSO-powered vertical solutions to SMEs, corporates and government.
   - Measure: contracted customers, seats, monthly recurring revenue, implementation revenue and gross margin.

5. **API/platform monetization**
   - Where commercially agreed, Econet can charge for API calls, transactions or platform usage.
   - Measure: billable API calls, successful actions and revenue per action.

## Attribution model

Every material THUSO action receives a trace ID and outcome event.

Required event chain:

`campaign/source -> AI session -> intent -> approved action -> API transaction -> outcome -> revenue`

No revenue claim is accepted unless the event chain is present.

## Pilot scorecard

THUSO should report:

- AI sessions
- unique AI users
- paid AI conversions
- AI package revenue
- incremental data usage
- EcoCash transaction count/value
- successful service completions
- enterprise accounts
- recurring revenue
- support interactions deflected
- task completion time
- cost per completed task
- attributable Econet revenue

## Proof method

Use a defined pilot cohort and baseline. Compare THUSO users with a suitable pre-pilot or matched control cohort, controlling for seasonality where possible.

The system must distinguish:
- observed revenue
- attributed revenue
- estimated/modelled value

Estimated value must never be presented as booked revenue.

## Commercial principle

NahaLabs sells the application/orchestration layer and measurable outcomes. Econet retains its agreed telecom, AI, wallet, connectivity and enterprise revenue streams. Commercial percentages and prices remain contractual rather than hard-coded.
